01 · THE PROBLEM

Why RTO is e-commerce's
silent profit killer

Return-to-Origin costs on Cash on Delivery orders can exceed 15–20% of gross merchandise value. Each failed delivery doubles the shipping expense — you pay to send it AND to bring it back.

📦

The RTO Crisis

When a COD customer refuses delivery, Meesho pays the forward shipping cost AND a reverse logistics cost to get the package back. With millions of orders daily, even small RTO rate changes have massive P&L impact.

🤔

The Routing Dilemma

Valmo is cheaper (₹35–42) but has variable performance across PIN codes. 3PL is more expensive (₹50–65) but more reliable. The challenge: choose the carrier that minimizes total expected cost per order.

03 · METHODOLOGY

Expected Monetary Value —
the decision engine

Instead of routing by cheapest carrier or by fixed rules, we compute the expected financial loss for each carrier on every order, then route to whoever scores lower.

CORE FORMULA · EMV ANALYSIS
EMV_Loss = P(RTO) × ( Cforward + Creverse )
P(RTO)
Historical return-to-origin probability for that PIN code and payment type. Ranges 10%–50% based on past fulfillment data.
Cforward
Initial delivery cost using the selected carrier. Becomes a sunk cost if the customer refuses the package.
Creverse
Cost to return the undelivered package to the origin facility. Roughly equals forward cost due to similar distance and handling.
01

Serviceability Check

If Valmo does not operate in the destination PIN code, the order must go to 3PL. No choice — coverage wins.

→ Force 3PL
02

High-Value Safety

Orders above ₹2,200 are routed to 3PL for insurance and reliability. The higher baseline cost is justified by lower risk exposure on expensive items.

→ Prefer 3PL
03

EMV Comparison

For all other orders, compute EMV_Loss for both Valmo and 3PL. Route to whichever produces the lower expected financial penalty.

→ Compare & Choose

df['EMV_Valmo'] = df['Historical_PIN_Risk'] * (df['Valmo_Cost'] * 2)
df['EMV_3PL']   = df['Historical_PIN_Risk'] * (df['3PL_Cost']   * 2)

# Routing Decision Engine — three rules in priority order
def route_order(row):
    if not row['Valmo_Serviceable']:      # Rule 1: no coverage
        return '3PL'
    if row['Order_Value_INR'] > 2200:    # Rule 2: high-value safety
        return '3PL'
    if row['EMV_Valmo'] <= row['EMV_3PL']: # Rule 3: EMV comparison
        return 'Valmo'
    return '3PL'

df['Assigned_Partner']    = df.apply(route_order, axis=1)
df['Final_Fulfillment_Cost'] = np.where(
    df['Assigned_Partner'] == 'Valmo',
    df['Valmo_Cost'], df['3PL_Cost']
)

# Export for Power BI visualization
